## Detailed Findings

### F-01: File input accessible name via `<label for>` only

**Severity:** Low
**Area:** Accessible names (category 2)

**Observed:** `document.querySelectorAll('button, input')` returned `#import-file` as the only element with no inline accessible name attribute (`aria-label`, `aria-labelledby`, `title`, `placeholder`). Its name comes entirely from `<label for="import-file">`. Confirmed: `document.querySelector('label[for="import-file"]').textContent.trim()` returns `"Import"` and `htmlFor` is `"import-file"`. The Playwright snapshot exposes the input as `button "Import"`, confirming the association works at runtime.

This is not a WCAG failure. The HTML pattern is correct. The risk is that if the label element is ever moved or the `for` value drifts, the input becomes unlabeled with no fallback.

**Suggested fix in `index.html`:** Add `aria-label="Import JSON data file"` to the `<input type="file">` element as a fallback.

### F-02: Import label/input creates redundant non-focusable container in accessibility tree

**Severity:** Low
**Area:** Accessible names, keyboard reachability (categories 1, 2)

**Observed:** Accessibility snapshot:
```
- generic [ref=e33] [cursor=pointer]:
  - text: Import
  - button "Import" [ref=e34]
```
The `<label>` renders as a `generic` node with `cursor=pointer` but no interactive role and no tab stop. The `<input type="file">` inside it is the actual `button "Import"`. On touch AT exploration the outer container could be perceived as a tappable element that does nothing, while the real control is a child.

**Suggested fix:** No change required for keyboard or screen-reader correctness. For robustness on touch AT, add `role="button"` and `tabindex="0"` to the `<label>` and trigger the input click on `keydown` for Enter/Space.

### F-03: Missing favicon generates 404 on every page load

**Severity:** Low
**Area:** Network / asset completeness (category 8)

**Observed:** Console on first load:
```
[ERROR] Failed to load resource: the server responded with a status of 404 (Not Found)
  @ http://localhost:4173/favicon.ico:1
```
`document.querySelector('link[rel*="icon"]')` returns `null`. No favicon `<link>` element is present in `index.html`.

**Suggested fix in `index.html`:** Add an inline SVG favicon to suppress the automatic browser request with no extra file:
```html
<link rel="icon" href="data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg'><text y='1em' font-size='1em'>&#9742;</text></svg>">
```

### F-04: Playwright snapshot shows stray "☎ ☎ ☎" text in `<main>` (artifact, no functional impact)

**Severity:** Low (snapshot artifact only)
**Area:** Presentation

**Observed:** After demo data loads and throughout subsequent section views, the Playwright accessibility snapshot shows `text: ☎ ☎ ☎` as a loose text node at the top of `<main>`, outside any `<section>`.

**DOM investigation results:**
- `document.getElementById('intro-panel').hidden`: `true`
- `window.getComputedStyle(introPanel).display`: `"none"`

The text comes from `.intro-points li::before { content: "☎"; }` CSS pseudo-elements on the three hidden list items. Playwright's accessibility tree extracts pseudo-element content from `display:none` subtrees. Real AT implementations (JAWS, NVDA, VoiceOver) do not expose content inside `display:none` elements, so there is no functional defect.

**Suggested fix:** No code change needed for real screen readers. If automated testing tools flag it, add `aria-hidden="true"` to `#intro-panel` when hiding it, or replace the CSS `::before` with `<span aria-hidden="true">☎</span>` inside each `<li>`.

### F-05: Fridge sheet on-screen preview omits individual contacts

**Severity:** Medium
**Area:** On-screen print previews (category 7)

**Observed:** With 5 demo contacts loaded, the fridge sheet preview in the Print section contains exactly:

```
"Our Dead Phone Directory"
"5 contacts · 3 to memorize · 3 emergency numbers"
"Plan: Front yard oak tree (demo) · Fallback: Dolores next door: 555-0105 (demo)"
"Printed date: 2026-11-18"
```

Confirmed via `document.querySelector('.fridge-preview').innerHTML`: four `<p>` elements, no contact rows.

The wallet card preview correctly shows individual rows (Emergency/911, Mom/(212) 555-0101, Dad/(212) 555-0102, Aunt Mavis/(212) 555-0103 on the front; plan + 988 + Poison Control on the back).

The `.print-fridge` DOM (the actual print target) is built correctly by `buildFridge()` with all contacts, emergency numbers, and the plan. Only the on-screen preview is a summary.

**Impact:** A user cannot verify individual contacts are correct before printing. Given the app's emergency use case, printing wrong data is a real failure mode.

**Suggested fix in `src/ui/print.ts`:** Extend `renderPreviewScreenOnly()` to enumerate individual contact rows inside `.fridge-preview`, using the same pattern already in place for the wallet preview. The `buildFridge()` function already has the full rendering logic; the preview just needs to mirror it at screen size.

### F-06: Drill card transition focus management consistent but not positively confirmed

**Severity:** Low
**Area:** Keyboard reachability (category 1)

**Observed:** After clicking "Next" on card 1, the card-2 snapshot shows the textbox as `[active]`, which Playwright marks when an element has focus at snapshot time. This is consistent with correct programmatic focus. However, `[active]` could also reflect natural browser behavior (e.g., focus falling to the first focusable element in the new card, or the user's Enter key on "Next" advancing focus). No scenario was observed where focus was lost between cards.

**Suggested fix:** Confirm `src/ui/drill.ts` calls `inputEl.focus()` explicitly after rendering each new card. If it does not, add it. Explicit focus calls are more reliable than relying on browser defaults, especially across AT/browser combinations.

---

### F-07: Drill feedback status region precedes card heading in DOM order

**Severity:** Low
**Area:** aria-live drill feedback (category 3)

**Observed:** After submitting a wrong answer, the DOM tree inside the drill session wrapper was:
```
- status: "✗ Missed. The number is (212) 555-0102."
- button "Next" [active]
- generic [card]:
  - paragraph "1 of 3"
  - paragraph "Dad (demo)"
  - paragraph "Father"
  - textbox [disabled]
```

The `role="status"` element (equivalent to `aria-live="polite"`) announces its content on change regardless of position, so the feedback is announced correctly when it appears. The ordering only matters in linear browse mode: a screen reader user navigating with arrow keys after the fact would read "Missed" then "Next" then "1 of 3" then "Dad (demo)", which is reversed from the natural card-then-feedback order.

**Suggested fix:** Reorder the DOM in `src/ui/drill.ts` so the status region sits after the card container, not before it.

## Areas With No Issues Found

### Keyboard reachability (overall)
Every interactive element is in the tab order: nav buttons (Directory, Drill, Plan, Print), theme toggle, "+ Add Contact", Load demo, Export, Import, Edit/Delete per contact, drill text input, Submit, Next, Print wallet card, Print fridge sheet, Save Plan. No traps. The delete confirmation dialog focuses the destructive "Delete" button, which is appropriate.

### Emergency numbers display
All three required numbers (911, 988 Suicide and Crisis Lifeline, Poison Control 1-800-222-1222) appear in a dedicated "Emergency Numbers" section. Poison Control is formatted "1 (800) 222-1222". No edit or delete controls are on these rows.

### Network isolation
All requests go exclusively to `http://localhost:4173`. Assets: one HTML, one JS bundle, one CSS bundle. No CDN fonts, analytics, external APIs, or third-party scripts at any point during the session.

### 320px viewport layout
`document.body.scrollWidth === 320`, `window.innerWidth === 320`. No horizontal scroll. Content reflows correctly.

### 390px viewport layout
`document.body.scrollWidth === 390`. No horizontal scroll. Contact rows reflow to two-row stacked layout (name/relation on row 1, phone/actions on row 2) as specified in `directory.css`.

### Dark mode
Theme toggle cycles System, Light, Dark. Under `data-theme="dark"` the computed body background is `rgb(28, 20, 9)` (#1c1409), matching the dark palette variable. Preference is persisted to `localStorage`.

### `prefers-reduced-motion`
`@media (prefers-reduced-motion: reduce)` rules suppress transitions on nav buttons, `.btn`, `#theme-toggle`, `.contact-row`, the letter heading `text-shadow`, and `scroll-behavior`. Coverage is comprehensive across all animated elements.

### Demo data load (R7)
"Try the demo" from the intro panel loads demo data without a confirm dialog when the directory is empty. The notice banner appears in `role="status" aria-live="polite"` and reads "Demo data loaded. These are fictional contacts using 555-01xx numbers." All 5 contacts use 555-01xx numbers. Three are flagged must-memorize (Mom, Dad, Aunt Mavis), satisfying the minimum-two requirement.

### Drill correct/incorrect answer flow
Wrong answer "5551234567" for Dad's "(212) 555-0102" produced `status: "✗ Missed. The number is (212) 555-0102."` with input and Submit disabled and Next focused. Correct answer "2125550101" for Mom's "(212) 555-0101" produced `status: "✓ Correct!"`. Both use `role="status"`, satisfying the `aria-live="polite"` requirement (R9 req 34).

### Contact edit/delete accessible names
Edit buttons carry `aria-label="Edit {name}"` and delete buttons carry `aria-label="Delete {name}"`, disambiguating them without visual context.

### Plan section
Both textarea fields (meeting place and fallback contact) have visible labels via correct `for`/`id` associations. Save Plan has visible button text. Pre-populated demo plan data renders correctly.

### Wallet card preview
On-screen wallet preview lists Emergency/911, Mom/(212) 555-0101, Dad/(212) 555-0102, Aunt Mavis/(212) 555-0103 on the front; and meeting place, fallback text, 988 Suicide and Crisis Lifeline, Poison Control on the back. Matches R4 requirements.

### Intro panel auto-hide (R10 req 41)
After demo load, `introPanel.hidden === true` and computed `display === "none"`. Panel is not shown when contacts are present. No extra localStorage field needed or used.
